## 一、主要问题修复（F）

<a id="f-01"></a>
### F-01 每日搭配食材池：未购清单不能当作已有

- 投入：低｜关联：[IDEA-019](IDEAS.md#idea-019) 候选 1
- 问题：[SKILL.md:274-278](../SKILL.md) 把未勾选（尚未购买）的清单条目算入食材池；清单为空时拒绝回答“今晚吃什么”，即使库存足够。
- 范围：区分“当下用餐”（只用库存）与“购后规划”（库存 + 已确认待购，并标明哪些需先买到）；清单为空不阻塞当下用餐。
- 验收：库存有蛋和青菜、清单为空 → 能给出今晚搭配；清单里的鱼不被描述为家里已有。

<a id="f-02"></a>
### F-02 过期不等于消失：去掉按日期删除

- 投入：低｜关联：[IDEA-019](IDEAS.md#idea-019) 候选 2
- 问题：[SKILL.md:443-451](../SKILL.md) Inventory Cleanup 删除过期条目，与 [SKILL.md:65](../SKILL.md)“过期不证明消耗”矛盾。
- 范围：过期只标记、不进入搭配食材池；用户报告丢弃、吃完或要求移除时才删除或减少。
- 验收：过期未处置的牛奶仍可查到并标为过期；用户说“扔了”后移除，且不产生耗尽信号。

<a id="f-03"></a>

- 范围：改为宿主无关表述（“若宿主支持定时任务，可安排以下检查”），只描述检查内容与提示文案；路径统一带 `[AGENT_HOME]`。
- 验收：`validate_static.py` 0 FAIL、0 WARN；全文无单一宿主命令。

<a id="f-04"></a>
### F-04 清理文档内矛盾

- 投入：低
- 问题：[SKILL.md:217](../SKILL.md) 青椒列在“水果”，[quantity_benchmark.md:38](../references/quantity_benchmark.md) 归“蔬菜”；SKILL.md 蛋白质类含豆制品，而基准单列豆制品；[schema.md:257](../references/schema.md) 免责声明指向“Weekly Plan section”，实为独立小节。

<a id="f-05"></a>
### F-05 收窄触发与初始化时机

- 投入：低
- 问题：[SKILL.md:3](../SKILL.md) description 的“食材咨询”覆盖一般烹饪提问；[SKILL.md:23](../SKILL.md) 要求任何请求前先建数据目录，误触发会留下数据文件。
- 范围：description 突出“结合家中库存／饮食画像”的场景；只读咨询不建目录，首次写操作时再初始化。
- 验收：“海带怎么炖好吃”这类与库存无关的提问不创建数据目录；“加牛奶”仍正常初始化。

<a id="f-06"></a>
### F-06 `status` 改为读取时计算

- 投入：低至中｜涉及 schema
- 问题：[schema.md:58](../references/schema.md) 存储 `fresh/expiring_soon/expired`，可由 `expires` 推出，存储后必然过时。
- 范围：新写入不再存 `status`，展示与检查时按 `expires` 和当天日期计算；旧字段兼容读取但不作依据。
- 验收：一条 3 天前写入、今天到期的条目，在查看时显示为即将过期／已过期，无需人工更新。

<a id="f-07"></a>
### F-07 显式记录规划时段

- 投入：中｜涉及 schema｜依赖 F-01
- 问题：每日搭配与周计划依赖“当前时段”，但 [shopping.json 条目](../references/schema.md) 无时段字段，周计划也未记录进行到哪一段，agent 只能猜。
- 范围：`confirmation` 记录本次计划的时段起止日期；合并入清单的条目保留来源计划 ID；周计划“继续下一段”据此定位。
- 验收：周日确认第一段后，周三说“继续下一段”，agent 能正确给出第二段日期范围且不重复第一段的待购项。

<a id="f-08"></a>
### F-08 `itemKey` 一致性规则

- 投入：中｜涉及 schema｜脚本支持见 A-02
- 问题：[schema.md:7](../references/schema.md) 只要求“确定时复用”，没有命名规范和查找顺序，长期会出现 `food_apple`／`food_apples` 分叉，导致去重和耗尽信号失效静默失败。
- 范围：规定命名规范（单数、统一语言、形态区分如 `food_mushroom_dried`）与新建前的查找顺序（pantry → shopping → 活跃 feedback → 最近历史）；可选在 pantry `meta` 中维护别名表。
- 验收：已有 `food_apple` 时说“买了几个苹果”“苹果吃完了”，各文件都复用同一 key；鲜香菇与干香菇不合并。

## 二、价值提升：修复削弱因素（V）

<a id="v-01"></a>
### V-01 降低单次操作的指令读取量

- 投入：中

- 范围：把普通增删改所需的最小字段规则内联到 SKILL.md；仅在涉及“吃完”、偏好或计划时读 feedback_flow；schema 作为字段查询而非必读。

<a id="v-02"></a>

<a id="v-03"></a>
### V-03 数据位置可指定、可共享（需研究）

- 投入：高｜需新增 RQ

- 范围：研究用户指定数据目录（如同步盘）的解析规则、指针存放位置与并发写冲突处理；不引入宿主专属配置。
- 验收：两个不同宿主指向同一目录时，一方入库后另一方能读到；并发冲突有定义好的处理方式。

<a id="v-04"></a>

- 验收：空画像用户的采购计划不出现“避免精制碳水”类取向；有控糖画像的用户行为不变。

<a id="a-01"></a>
### A-01 重新定位

- 范围：README 开头与 description 改为“按家里现有食材和饮食约束，规划买什么、怎么吃”；库存与购买记录作为支撑能力列在后面。对应 [收敛建议](convergence-review-2026-09-28.md) 第 6 项。
- 验收：README 前三行能让新用户找到“买什么／怎么吃”入口。

<a id="a-02"></a>
### A-02 运行时脚本 `scripts/`

- 范围：零依赖脚本，覆盖 JSON 合法性与 schema 校验、`history` stats 重算、`itemKey` 查找／新建（配合 F-08）、过期状态计算（配合 F-06）。SKILL.md 写明“有 shell 时运行，否则按文字规则执行”（硬规则 #2）。
- 验收：一份字段缺失或 stats 错误的 fixture 被脚本检出；无 shell 的宿主仍能完成全部操作。

<a id="a-03"></a>
### A-03 golden cases 跨宿主执行

- 范围：`run_golden.py` 的 executor 接入至少两种宿主的非交互模式；全部 golden cases 各跑一轮，结果连同宿主与模型版本存入 dev/。
- 验收：通过率报告可复现；失败项各自对应一个 IDEA 或已知限制。

<a id="a-04"></a>
### A-04 推荐宿主与语音示例

- 范围：README 兼容性说明区分“推荐宿主”（常驻、聊天渠道、语音、定时能力的个人助理型 agent）与“开发测试用宿主”（IDE／编码 agent）；补一句话多项操作的语音示例和简短回执样例。
- 验收：README 能说明在哪类宿主上使用效果最好，以及原因。

<a id="a-05"></a>
### A-05 发布与演示材料

- 依赖：A-01、A-03
- 范围：一段完整对话演示（采购计划 → 确认 → 买了 → 今晚吃什么 → 吃完了 → 下次计划提示补购）；在 skill 目录与相关社区发布。
- 验收：演示与当前契约一致，不展示未实现能力。

<a id="a-06"></a>
### A-06 家庭多人使用

- 依赖：V-03
- 范围：在共享数据目录基础上，区分成员画像与共享库存／清单；定义谁的偏好用于全家采购计划。
- 验收：两名成员分别报告“买了”“吃完了”，库存与清单保持一致，各自偏好不互相覆盖。
